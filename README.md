## 📬 How to Submit Feedback

### Method 1: The In-Page Feedback Widget (Recommended)
Every documentation page and hands-on lab on [https://bootcamp.kong-demo.com](https://bootcamp.kong-demo.com) includes a feedback widget at the bottom:
1. Scroll to the bottom of the lab page.
2. Select **👍 Yes** or **👎 Needs Improvement**.
3. Click **💬 Partner Feedback**. This generates a pre-formatted GitHub issue URL containing the exact page title, public URL, and machine-readable remediation context.
4. Add your comments and click **Submit new issue**.

### Method 2: GitHub Issue Templates
If you want to file a detailed bug or suggest a new topic directly:
- 🐛 **[Broken Lab / Bug Report](https://github.com/kong-partner-solutions/kong-bootcamp-feedback/issues/new?template=02_broken_lab.yml)**: Report a command syntax error, Docker Compose crash, plugin version conflict, or decK sync failure.
- 💬 **[Page & Lab Feedback](https://github.com/kong-partner-solutions/kong-bootcamp-feedback/issues/new?template=01_page_feedback.yml)**: General suggestions, typo corrections, or missing explanations.
- 💡 **[New Lab / Topic Proposal](https://github.com/kong-partner-solutions/kong-bootcamp-feedback/issues/new?template=03_topic_request.yml)**: Request new architecture deep-dives, Kong plugins, or hands-on lab scenarios.

## 🔒 Security & Privacy Notice

> [!CAUTION]
> **This is a PUBLIC repository.**
> - **NEVER** share Kong Konnect Personal Access Tokens (`kpat_...`), API keys, passwords, or client secrets.
> - **NEVER** include un-redacted terminal outputs containing internal infrastructure hostnames, credentials, or proprietary enterprise data.
> - Sanitize logs with placeholder values like `<KONNECT_TOKEN>` or `<REDACTED>`.

If you have discovered a potential security vulnerability in Kong products or platform infrastructure, please follow our [Security Policy](SECURITY.md) and email **[security@konghq.com](mailto:security@konghq.com)** directly.

## 🤖 Automated Remediation Pipeline

Issues submitted through our in-page feedback widget contain an `<!-- agent-metadata ... -->` comment block. This metadata enables our continuous enablement pipeline to:
1. Automatically tag the issue with the appropriate bootcamp label.
2. Link the feedback to the specific source markdown document in our build repository.
3. Rapidly validate corrections, re-build VitePress bundles, and push delta updates to AWS CloudFront.
